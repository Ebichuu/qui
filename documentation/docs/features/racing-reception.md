---
title: 下载器接种（开发中）
---

接种默认关闭。在设置 → 下载器中配置群组、物理存储池和路径映射，再为需要接种的下载器开启“下载器接种”。站点需要填写 Tracker 域名，用于核实种子文件与目标任务是否属于同一站点及账号。启用前停止同一范围内 qBittorrent 或 Vertex 的自动添加，避免两个执行者同时工作。

启用来源、规则或加入群组本身不会开启接种。关闭下载器接种会阻止后续提交；已发送但结果未知的请求继续在原下载器核实，保留原规则、目标和空间预留。此功能不授予删除、修改 Tracker 或主动汇报权限。

## 选择下载器和预留空间

先使用一条完整命中规则确定目标。群组不可用时等待该群组；不会降级到另一条规则的群组。官种优先排队，同类按首次发现时间处理。候选需要验证后的真实 hash、准确大小和原始种子文件，缺少时独立补取，不等待整批元数据。

选机排除停用、不健康、状态过期、路径未知、容量不足或名额已满的实例，再比较当前下载负载、名额、可用空间和最近分配。每个实例有自己的并发添加上限；一台实例请求缓慢不阻塞其他实例。

物理存储池统一计算所有映射实例的磁盘承诺，跨群组也不能重复使用容量：

- 磁盘余量与任务完成量来自同一份现有同步缓存，不启动第二个状态轮询。
- 同盘余量取新鲜观测中的最小值，已有任务未来写入相加。暂停、排队任务也计入；下载流量不能当作已完成文件大小。
- 临时与最终目录不同盘时，临时盘需要剩余下载空间，最终盘还需要完整文件的写入空间。
- 默认目录的余量只证明其所属磁盘有空间，不能替其他磁盘证明容量。容量未知或共享成员状态过期时等待。
- 添加尚未确认时保留整份预留；任务及 Tracker 确认后，只有包含该任务的容量快照才能用实际未来写入替代原预留，避免漏算或重复扣算。

配置“下载名额”时，未完成任务与未决添加均占用名额。“添加后暂停”不会被程序自动恢复；接种记录中任务已确认也不代表它已开始运行。

## 查看与恢复

RSS → qui 统一来源 → 规则下的“接种记录”分别显示空间预留、请求发送、请求受理、任务确认、观察到可运行及首次传输时间。

| 状态 | 行为 |
|---|---|
| 已预留空间 | 尚未发送；配置、证据或窗口变化可取消后重评 |
| 请求已发送／结果未知 | 保留原目标与预留，只核实，不盲目重发 |
| 请求已受理 | 接口返回成功，仍需确认任务和账号 Tracker |
| 任务及 Tracker 已确认 | 继续观察可运行及传输状态 |
| 发送前已取消 | 没有发送，空间预留已释放，可按最新证据重评 |
| 已确认任务已移除 | 新鲜观测连续至少 30 秒确认任务消失，释放预留，保留原事件历史 |

同一 hash 已存在时，程序查询真实 Tracker 列表并与种子文件中的完整地址比较。仅域名相同、账号参数不同不能算本站已接种，也不会通过重复添加来合并 Tracker。首版没有多实例重复参与开关，已有同 hash 任务或意图时不会在另一实例自动创建副本。URL 规范化差异可能导致保守等待，需要核实原因，不会放松账号校验。

预留和发送边界均持久化。进程在发送边界崩溃时，重启后按“可能已发送”处理。找不到任务不能证明请求失败，因此不自动释放预留或换机重投。已确认任务移除后，连续新鲜观测核实消失才释放预留；观测中断超过 10 秒会重新计时。原事件不会重放，后续独立复活事件可再次参与。原始种子文件单独加密保存，接种接口与日志不返回私密 Tracker 地址。

添加通知复用现有异步通知队列和通知目标配置。通知延迟或失败不改变接种结果，不触发再次添加，也不占用后续接种名额。

## 当前限制

开发验证使用本机合成来源和模拟下载器。实际站点、生产数据库副本、真实共享磁盘及旧自动化交接仍需 C09/C13 现场验证。无法证明容量或 Tracker 身份时会等待；未决请求尚无自动放弃或人工重发入口。本批不执行官种腾空间、删除或 Tracker 汇报。
