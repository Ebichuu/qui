---
title: 来源发现（开发中）
---

竞速扩展可在 qui 后台独立观察 RSS 和网页来源。当前阶段仅记录发现；不会添加、删除种子或修改下载器。在原 RSS 页面的“管理范围”选择“qui 统一来源”，即可配置 RSS、网页和复活列表；“qBittorrent 原有 RSS”保留未交接配置的管理入口。

## 来源能力

| 适配器 | 类型 | 当前可读取的证据 |
|---|---|---|
| `generic-rss` | RSS 2.0 | 标题、大小、发布时间、显式报告的 hash 和免费计费因子 |
| `chd` | RSS、普通网页、复活网页 | RSS 字段、完整网页标题、官种标记、免费标记、符合约定的复活时间 |
| `mteam` | RSS | 详情路径中的站内 ID、RSS 字段和显式计费因子 |

这些适配器已建立合成格式夹具。能力接口中的 `synthetic_fixtures` 表示合成验证，实际站点登录与页面兼容性仍待现场验证。缺少免费或官种证据时保持“未知”。来源报告的 hash 也需要后续用种子元数据核实。

## 抓取与恢复

RSS 和网页各自抓取。完整 RSS 条目与已解析网页页立即保存，慢来源或后续页不会挡住先到的条目。同站配置共用请求频率预算；失败仅使对应来源退避重试。

来源可配置适配器、页数与初始回看秒数。普通 CHD 网页最多五页；复活网页单页。未选择支持的网页适配器时不会抓取。初始回看默认零，仅在首次有效抓取前建立基线时使用。之后重启或编辑配置不回退基线，防止旧条目重新变成新发现。

旧条目仍保留观察记录。缺少事件时间的条目不会成为有效候选。记录中的 `eligible` 只表示通过来源基线，规则接收窗口、目标与其他条件由后续规则处理决定。

## 只读接口

经过认证后，`GET /api/racing/discoveries` 返回最近 100 项发现、各来源的最近成功时间、下次尝试时间和错误分类，以及适配器能力。界面和接口不返回来源凭据、下载地址或详情地址。这些私密字段加密保存。

停用来源或站点会取消相应抓取。修改配置后，旧响应不能继续更新发现记录。删除来源会删除其观察记录；已有规则引用的来源仍需先解除引用。

## 页面配置

在“订阅源”页签先添加站点，再添加来源。站点保存源地址、Cookie、Tracker 主机名及最小请求间隔；来源选择站点格式、地址、轮询间隔、网页页数和首次回看秒数。新增配置默认停用，启用仅启动后台观察。

编辑来源时，地址留空保留原值；编辑站点时，Cookie 留空保留原值，只有勾选清除才删除已保存 Cookie。私密内容不会从配置接口回填到表单。列表显示采集状态和最近成功时间，关闭页面不会停止后台采集。

“迁移预览”可读取所选下载器的现有 RSS，也可在浏览器本地读取 Vertex 的单个 RSS 任务、RSS 规则或网页监控 JSON。集合格式为 `rss`、`rules`、`webMonitors` 三个可选数组，大小上限为 2 MiB。预览不会导入或启停任何配置。

原字段、原值及建议映射逐项列出。路径、分类、暂停/启动、自动管理、正则、剧集过滤、脚本及未识别设置不会静默丢弃。Vertex 的接收/拒绝规则是 ID 引用，免费检查是任务级后置检查，多个条件可能按“且”组合；这些都不能直接改成新接收类型的“或”。Cron、随机间隔和目标下载器 ID 也需核对。迁移时仍需重新确认站点账号及 Cookie，不从隐藏预览值重建凭据。

URL 私密部分和凭据在预览中隐藏；原导出仅保留在当前浏览器内存。原 qB 自动下载规则保持原行为，实际交接另行进行。
